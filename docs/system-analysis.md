Software Analysis Document

1. معرفی سیستم

Silver Price Ledger System یک سیستم Backend برای جمع‌آوری، ذخیره‌سازی، ارائه و پیش‌بینی قیمت نقره است.

این سیستم با استفاده از FastAPI توسعه داده شده و اطلاعات قیمت نقره را از چند منبع آنلاین دریافت کرده و در پایگاه داده PostgreSQL ذخیره می‌کند.

سیستم علاوه بر ارائه قیمت‌های فعلی و تاریخی، امکان پیش‌بینی قیمت آینده نقره را با استفاده از مدل‌های یادگیری ماشین فراهم می‌کند.

---

2. هدف پروژه

اهداف اصلی سیستم عبارت‌اند از:

- جمع‌آوری خودکار قیمت نقره از چند منبع آنلاین
- ذخیره‌سازی اطلاعات تاریخی قیمت
- ارائه API برای دسترسی به اطلاعات قیمت
- تهیه داده‌های مناسب برای تحلیل و پیش‌بینی
- پیش‌بینی قیمت آینده نقره با استفاده از الگوریتم‌های یادگیری ماشین
- اجرای خودکار فرآیند جمع‌آوری اطلاعات در بازه‌های زمانی مشخص

---

3. محدوده سیستم

سیستم در حال حاضر به‌صورت Backend طراحی شده و وظایف اصلی آن شامل موارد زیر است:

- دریافت اطلاعات از منابع قیمت
- نرمال‌سازی داده‌های دریافتی
- ذخیره اطلاعات در PostgreSQL
- ارائه APIهای مربوط به قیمت
- آماده‌سازی داده برای مدل‌های پیش‌بینی
- آموزش و ذخیره مدل‌های یادگیری ماشین
- ارائه پیش‌بینی از طریق API
- احراز هویت کاربران برای دسترسی به APIهای محافظت‌شده

رابط کاربری مستقل در محدوده فعلی پروژه قرار ندارد.

---

4. منابع داده

قیمت نقره از سه منبع زیر دریافت می‌شود:

- TGJU
- Silfam
- NoghrehSea

برای هر منبع، Scraper یا منطق دریافت متناسب با ساختار آن منبع پیاده‌سازی شده است.

داده‌های دریافتی قبل از ذخیره‌سازی نرمال‌سازی می‌شوند تا قالب قیمت و زمان در کل سیستم یکسان باشد.

---

5. فرآیند جمع‌آوری داده

فرآیند جمع‌آوری قیمت به‌صورت زیر انجام می‌شود:

1. Collector فرآیند جمع‌آوری را آغاز می‌کند.
2. اطلاعات از منابع مختلف دریافت می‌شود.
3. داده‌های دریافت‌شده نرمال‌سازی می‌شوند.
4. قیمت و اطلاعات زمانی مربوط به هر رکورد مشخص می‌شود.
5. داده در پایگاه داده PostgreSQL ذخیره می‌شود.
6. در صورت خطای یک منبع، امکان ادامه فرآیند برای سایر منابع وجود دارد.
7. Scheduler امکان اجرای خودکار فرآیند Collector را فراهم می‌کند.

در داده‌های ذخیره‌شده دو زمان اصلی وجود دارد:

- "fetched_at": زمان مربوط به دریافت یا استخراج داده از منبع
- "created_at": زمان ایجاد رکورد در سیستم

در مرحله آماده‌سازی داده‌های پیش‌بینی، "created_at" به‌عنوان معیار نزدیک‌سازی زمانی بین داده‌های منابع مختلف استفاده می‌شود.

---

6. ارائه اطلاعات قیمت

سیستم APIهای مختلفی برای دسترسی به اطلاعات قیمت ارائه می‌کند.

مهم‌ترین APIهای مربوط به قیمت عبارت‌اند از:

- دریافت آخرین قیمت‌ها
- دریافت تاریخچه قیمت
- دریافت داده‌های مورد نیاز برای نمودار

اطلاعات از طریق سرویس‌های داخلی سیستم از پایگاه داده دریافت شده و سپس توسط API در اختیار مصرف‌کننده قرار می‌گیرد.

---

7. آماده‌سازی داده برای پیش‌بینی

برای ایجاد داده مناسب جهت آموزش و پیش‌بینی، اطلاعات سه منبع بر اساس زمان با یکدیگر ترکیب می‌شوند.

برای این منظور، رکوردهای منابع با استفاده از "created_at" و با یک محدوده زمانی مشخص به یکدیگر نزدیک می‌شوند.

پس از ترکیب داده‌ها، میانگین قیمت سه منبع به‌عنوان مقدار "silver_price" محاسبه می‌شود.

سپس ویژگی‌های زمانی و آماری زیر ایجاد می‌شوند:

- قیمت منابع مختلف
- "lag_1"
- "lag_2"
- "lag_3"
- "ma_3"
- "ma_5"
- "price_change"

مقدار هدف مدل نیز قیمت رکورد بعدی ("next_price") است.

---

8. مدل‌های پیش‌بینی

در سیستم دو الگوریتم یادگیری ماشین استفاده شده است:

Linear Regression

این مدل برای ایجاد یک رابطه خطی بین ویژگی‌های ورودی و قیمت آینده استفاده می‌شود.

Random Forest Regressor

این مدل از مجموعه‌ای از درخت‌های تصمیم استفاده می‌کند و برای مدل‌سازی روابط غیرخطی میان ویژگی‌ها و قیمت آینده به کار می‌رود.

داده‌ها به‌صورت زمانی به دو بخش آموزش و آزمون تقسیم می‌شوند و عملکرد مدل‌ها با معیارهای زیر ارزیابی می‌شود:

- MAE
- RMSE

پس از آموزش، مدل‌ها در قالب فایل ذخیره می‌شوند تا در زمان درخواست پیش‌بینی مجدداً مورد استفاده قرار گیرند.

---

9. API پیش‌بینی

سیستم یک API برای دریافت پیش‌بینی قیمت ارائه می‌کند.

با فراخوانی این API:

1. مدل Linear Regression بارگذاری می‌شود.
2. مدل Random Forest بارگذاری می‌شود.
3. آخرین داده‌های مورد نیاز از پایگاه داده دریافت می‌شوند.
4. ویژگی‌های پیش‌بینی آماده می‌شوند.
5. هر دو مدل قیمت آینده را پیش‌بینی می‌کنند.
6. نتایج در پایگاه داده ذخیره می‌شوند.
7. نتیجه پیش‌بینی از طریق API بازگردانده می‌شود.

---

10. احراز هویت

سیستم از JWT Authentication برای محافظت از APIهای نیازمند احراز هویت استفاده می‌کند.

پس از ورود موفق کاربر، یک Access Token ایجاد می‌شود و درخواست‌های محافظت‌شده باید این Token را ارسال کنند.

در سمت Backend، اعتبار Token بررسی شده و سپس دسترسی کاربر به Endpoint مربوطه انجام می‌شود.

---

11. پایگاه داده

پایگاه داده سیستم PostgreSQL است.

اطلاعات اصلی سیستم شامل داده‌های زیر است:

- کاربران
- منابع قیمت
- قیمت‌های دریافت‌شده
- نتایج پیش‌بینی

مدیریت تغییرات ساختار پایگاه داده با استفاده از Alembic انجام می‌شود.

---

12. زمان‌بندی اجرای سیستم

برای اجرای خودکار فرآیند جمع‌آوری قیمت از Scheduler استفاده شده است.

Scheduler فرآیند Collector را در بازه زمانی تعیین‌شده اجرا می‌کند و Collector وظیفه دریافت و ذخیره اطلاعات منابع را بر عهده دارد.

---

13. ساختار کلی سیستم

ساختار Backend به‌صورت ماژولار طراحی شده و بخش‌های اصلی آن شامل موارد زیر هستند:

- API
- Authentication
- Collectors
- Scrapers
- Services
- Prediction
- Models
- Database
- Scheduler

هر بخش وظیفه مشخصی دارد و منطق مربوط به دریافت داده، پردازش، ذخیره‌سازی و ارائه اطلاعات تا حد امکان از یکدیگر جدا شده‌اند.

---

14. استقرار

سیستم از Docker برای اجرای پایگاه داده PostgreSQL استفاده می‌کند.

تنظیمات محیطی و اطلاعات اتصال پایگاه داده از طریق فایل ".env" مدیریت می‌شوند.

کتابخانه‌ها و وابستگی‌های پروژه نیز در فایل "requirements.txt" تعریف شده‌اند.

---

15. تست

برای بررسی صحت عملکرد بخش‌های اصلی پروژه از "pytest" استفاده شده است.

تست‌ها بخش‌هایی مانند موارد زیر را پوشش می‌دهند:

- آماده‌سازی ویژگی‌های پیش‌بینی
- APIهای قیمت
- API پیش‌بینی
- عملکرد بخش‌های اصلی
- برخی رفتارهای Collector

همچنین تست‌های Performance برای بررسی زمان پاسخ APIها و عملکرد درخواست‌های همزمان در نظر گرفته شده‌اند.

---

16. جمع‌بندی

Silver Price Ledger System یک Backend ماژولار برای جمع‌آوری، ذخیره‌سازی، ارائه و پیش‌بینی قیمت نقره است.

سیستم با استفاده از FastAPI، PostgreSQL، Scheduler و الگوریتم‌های یادگیری ماشین پیاده‌سازی شده و امکان دریافت اطلاعات از چند منبع، پردازش داده‌ها و ارائه پیش‌بینی قیمت آینده را فراهم می‌کند.

جزئیات فنی مربوط به الگوریتم‌های پیش‌بینی، ویژگی‌های مورد استفاده، فرآیند آموزش و نحوه استفاده از مدل‌ها در مستند اختصاصی ماژول Prediction ارائه خواهد شد.
